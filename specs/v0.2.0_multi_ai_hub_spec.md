# 따로또같이 Multi-AI Hub (선행 단계) 구현 명세서

> 이 문서는 사용자가 보유한 다중 AI(ChatGPT, Claude, Gemini, Grok, Local LLM, OpenRouter)를 묶어서 활용할 수 있는 터미널 CLI 도구의 작업 지시서입니다.

## 0. 배경 및 목적

`apart-and-together`의 본격적인 협업 플랫폼 확장에 앞서, **사용자가 보유한 무료 및 구독/API 기반의 다양한 AI 모델들을 하나의 터미널 CLI 도구로 묶어서 손쉽게 제어하고 활용하는 선행 도구(Multi-AI Hub)**를 구축한다.

### 대상 모델 및 프로바이더
1. **OpenAI**: ChatGPT (`gpt-4o`, `gpt-4o-mini`, `o1` 등)
2. **Anthropic**: Claude (`claude-3-5-sonnet`, `claude-3-haiku` 등)
3. **Google**: Gemini (`gemini-1.5-pro`, `gemini-1.5-flash`, `gemini-2.0-flash` 등)
4. **xAI**: Grok (`grok-2`, `grok-beta` 등)
5. **OpenRouter**: 올인원 게이트웨이 (`openrouter.ai`)
6. **Local LLM**: Ollama / 로컬 OpenAI 호환 엔드포인트 (`localhost:11434`)

## 1. 만들 것

### 1.1. Multi-AI 코어 엔진 (`src/multi_ai/`)

외부 대형 프레임워크 의존 없이 표준 라이브러리와 `requests` 기반의 가볍고 빠른 엔진으로 구현한다.

- `src/multi_ai/config.py`:
  - 환경변수 및 `.env` 파일 파싱
  - 지원 환경변수: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, `XAI_API_KEY`, `OPENROUTER_API_KEY`, `OLLAMA_BASE_URL`
  - 현재 유효한 API 키를 가진 모델 목록 자동 감지(`detect_active_providers`)
- `src/multi_ai/providers/`:
  - `base.py`: 프로바이더 추상 기본 클래스 (`LLMResponse`, `BaseProvider`)
  - `openai_compat.py`: OpenAI 호환 프로바이더 (OpenAI, Grok, OpenRouter, Ollama)
  - `anthropic.py`: Anthropic Claude 전용 프로바이더
  - `gemini.py`: Google Gemini REST 프로바이더
- `src/multi_ai/hub.py`:
  - `ThreadPoolExecutor`를 활용한 병렬 비동기 질의 (`query_all`, `query_models`)
  - 응답 시간(latency), 토큰 추정, 에러 격리(한 모델이 실패해도 다른 모델 응답 정상 수집)
  - 종합(Synthesize) 기능: 여러 AI의 답변을 하나의 종합 보고서로 취합

### 1.2. 터미널 CLI 인터페이스 (`src/multi_ai/cli.py` & 실행 스크립트)

사용자 친화적인 콘솔 명령어 지원:
1. `multi-ai status`:
   - 현재 등록된 API 키와 사용 가능한 활성 AI 모델 목록 확인
2. `multi-ai ask "<프롬프트>"`:
   - 등록된 모든 AI(또는 `--models gpt,claude`)에 동시 질의하고 답변을 분할/비교 출력
3. `multi-ai synth "<프롬프트>"`:
   - 여러 AI의 답변을 취합하여 최선의 종합 답변 생성
4. `multi-ai code "<과제 요구사항>"`:
   - 각 AI에게 코드를 작성하게 한 뒤, Phase 1의 `ast_scanner.py`를 호출하여 각 AI 코드의 보안성(AST 위험 호출 여부)을 즉시 교차 검증

### 1.3. 설정 템플릿 (`.env.example`)

사용자가 API 키를 쉽게 입력할 수 있는 템플릿 제공.

### 1.4. 단위 테스트 (`tests/test_multi_ai.py`)

- Mock HTTP 응답을 통한 각 프로바이더(OpenAI, Claude, Gemini, Grok, Ollama) 파싱 테스트
- 다중 질의 및 에러 격리 테스트
- CLI 인자 파싱 및 status 출력 테스트

## 2. 확장 경로 (Future Enhancements)

- 본 CLI 허브가 완성되면, 향후 이를 **MCP Server (`src/mcp_server.py`)**로 래핑하여 Claude Desktop, Cursor 등에서 툴 형태로 다른 AI를 호출할 수 있도록 확장한다.

## 3. 검증 포인트

- 단위 테스트 전수 통과
- `python3 -m src.multi_ai.cli status` 정상 실행 확인
- API 키가 없는 경우 친절한 안내 메시지 출력 확인
