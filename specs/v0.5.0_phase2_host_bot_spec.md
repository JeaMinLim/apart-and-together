# 따로또같이 Phase 2 호스트 AI 봇 및 재시도/재할당 자동화 구현 명세서

> 이 문서는 호스트 사람의 개입을 최소화하고, 과제 수락 기준 초안 자동 작성과 검증 실패 시 재시도/재할당 라이프사이클을 자동화하는 Phase 2의 작업 지시서입니다. 설계 배경 전체는 [DESIGN.md](../DESIGN.md)를 참고하세요.

---

## 0. 범위 및 목적 — 왜 Phase 2인가?

`DESIGN.md` §4에 정의된 Phase 2의 핵심은 **"호스트 AI 봇 (GitHub 연동 + 경량 백엔드 + 상태 머신)"**이다.
- Phase 0에서는 사람이 손으로 이슈 폼을 작성하고 수락/배정/재할당을 직접 처리했다.
- Phase 1에서는 제출된 PR에 대해 GitHub Actions 기반의 AST 보안 감사 및 단위 테스트 자동 검증 파이프라인을 구축했다.
- **Phase 2의 목표**: 사람이 수동으로 하던 다음 두 가지 핵심 병목을 호스트 AI 봇이 대신 처리한다:
  1. **과제 등록 자동화 ([DESIGN.md §2.6](file:///home/rocky/agents/apart-and-together/DESIGN.md#L62-L65))**: 사용자가 자유 서술로 목표를 적으면, AI가 검증 가능한 3단 수락 기준(인터페이스 스펙, 테스트 케이스, 비고) 초안을 작성하고 승인 게이트를 제공.
  2. **재시도 및 재할당 상태 기계 ([DESIGN.md §2.3, §2.4](file:///home/rocky/agents/apart-and-together/DESIGN.md#L39-L52))**: 검증 실패 시 작업자당 1회 재시도 부여 → 재실패 시 기존 코드를 보존한 채 다음 참여자에게 인계하는 재할당(최대 2회 상한)을 자동 집행.

## 1. 만들 것

### 1.1. 수락 기준 자동 초안 작성기 (`src/host_bot/draft_generator.py`)

- **입력**: 과제 등록자의 자유 서술 텍스트 (예: *"CSV 파일 업로드받아서 통계 내는 기능 필요해"*)
- **처리**: `MultiAIHub`를 호출하여 호스트 AI 프롬프트 실행
- **출력 (3단 구조 수락 기준 블록)**:
  1. **인터페이스 스펙 (Interface Spec)**: 함수명, 매개변수 타입, 반환형 시그니처
  2. **테스트 케이스 (Test Cases)**: 기계적으로 채점 가능한 구체적 입출력 케이스 (정상 케이스, 빈 값, 엣지 케이스 등)
  3. **비고 (Notes)**: 보안 제약 조건 (SQL Injection 방지, 메모리 제한 등)
- **승인 게이트 (Fail-closed Gate)**:
  - 등록자가 초안을 확인하고 명시적으로 승인(Approve)하기 전까지 과제는 `PENDING_APPROVAL` 상태로 잠기며 공개되지 않음.

### 1.2. 과제 라이프사이클 및 재시도/재할당 상태 머신 (`src/host_bot/lifecycle.py`)

- **스토리지**: SQLite 경량 DB (`.state/tasks.db`)
- **과제 상태 전이 (State Machine)**:
  ```text
  [자유서술 등록] ──> DRAFT
                    │
                    ▼ (AI 초안 생성 완료)
              PENDING_APPROVAL ──(수정 및 승인)──> OPEN (수락 대기)
                                                  │
                                                  ▼ (작업자 확정)
                                               ASSIGNED
                                                  │
                                                  ▼ (PR 제출)
                                              SUBMITTED
                                                  │
                      ┌───────────────────────────┴───────────────────────────┐
                      ▼ (Phase 1 검증 통과)                                   ▼ (Phase 1 검증 실패)
                   PASSED                                                 RETRY_1 (1차 재시도 부여)
                      │                                                       │
                      ▼                                    ┌──────────────────┴──────────────────┐
                   MERGED (완료)                           ▼ (재시도 통과)                        ▼ (재시도 실패)
                                                        PASSED                               REASSIGNED_1 (제2작업자 인계)
                                                                                                  │
                                                                           ┌──────────────────────┴──────────────────────┐
                                                                           ▼ (제2작업자 통과)                             ▼ (제2작업자 실패)
                                                                        PASSED                                       REASSIGNED_2 (제3작업자 최종 인계)
                                                                                                                          │
                                                                                                    ┌─────────────────────┴─────────────────────┐
                                                                                                    ▼ (통과)                                    ▼ (실패)
                                                                                                 PASSED                             FAILED_PERMANENTLY (영구 실패/과제 재설계)
  ```
- **엄격한 상한 규칙 ([DESIGN.md §2.3](file:///home/rocky/agents/apart-and-together/DESIGN.md#L39-L48))**:
  - `MAX_RETRIES_PER_WORKER = 1` (작업자당 재시도는 1회만 허용)
  - `MAX_REASSIGNMENTS = 2` (재할당은 최대 2회까지만 허용, 총 참여 인원 최대 3명)
  - 상한 초과 시 과제는 `FAILED_PERMANENTLY`로 마감되며, 무한 재시도로 인한 자원 고갈(Denial-of-Wallet)을 차단.
- **원본 브랜치 보존 및 인계 패키징 ([DESIGN.md §2.4, §2.5](file:///home/rocky/agents/apart-and-together/DESIGN.md#L49-L61))**:
  - 재할당 시 원 기여자의 브랜치(`feat/<task>-<user1>`)를 삭제하지 않음.
  - 새 참여자의 브랜치(`feat/<task>-<user1>-<user2>`)가 원본 커밋 위에서 생성되도록 베이스 브랜치 지정.
  - 직전 시도의 실패 원인 요약(AST 보안 위반 위치, 미통과 테스트 케이스)을 구조화된 컨텍스트로 생성하여 다음 참여자에게 전달.

### 1.3. 이벤트 디스패처 (`src/host_bot/dispatcher.py`)

- GitHub Issue / PR / Check Run 이벤트 수신 시 라이프사이클 상태 기계와 연동:
  - `on_issue_created(issue_title, issue_body, author)`:
    - 자유 서술 감지 시 `draft_generator` 호출 → 3단 수락 기준 초안 댓글 작성 → `PENDING_APPROVAL` 상태 저장
  - `on_issue_approved(task_id, approver)`:
    - 과제 등록자의 승인 확인 시 `OPEN` 상태로 변경 및 `task`, `대기중` 라벨 설정
  - `on_pr_opened(task_id, pr_number, contributor, branch_name)`:
    - `ASSIGNED` / `SUBMITTED` 상태 전이
  - `on_verification_completed(task_id, passed, error_summary, ast_report)`:
    - 통과 시: `PASSED` 전이
    - 실패 시: 잔여 재시도 카운트 확인 후 `RETRY_1` 또는 `REASSIGNED_1` 상태 전이 및 인계 코멘트 출력

### 1.4. 호스트 봇 CLI 인터페이스 (`bin/multi-ai bot ...`)

터미널에서 호스트 봇의 동작을 테스트하고 수동 제어할 수 있는 CLI:
- `multi-ai bot draft "<자유 서술 목표>"`: 수락 기준 초안 즉시 생성
- `multi-ai bot list`: 현재 추적 중인 과제들의 상태, 재시도 횟수, 재할당 횟수 표시
- `multi-ai bot approve <task_id>`: 등록자 승인 처리
- `multi-ai bot fail <task_id> --reason "테스트 실패"`: 검증 실패 시뮬레이션 및 재시도/재할당 상태 전이 검증

## 2. 데이터베이스 스키마 (`.state/tasks.db`)

```sql
CREATE TABLE tasks (
    task_id TEXT PRIMARY KEY,
    title TEXT NOT NULL,
    raw_description TEXT NOT NULL,
    interface_spec TEXT,
    test_cases TEXT,
    notes TEXT,
    creator TEXT NOT NULL,
    current_worker TEXT,
    status TEXT NOT NULL,
    retry_count INTEGER DEFAULT 0,
    reassign_count INTEGER DEFAULT 0,
    current_branch TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE task_history (
    history_id INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id TEXT NOT NULL,
    worker TEXT NOT NULL,
    branch_name TEXT,
    action TEXT NOT NULL, -- 'SUBMIT', 'RETRY', 'REASSIGN', 'PASS', 'FAIL'
    details TEXT,
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(task_id) REFERENCES tasks(task_id)
);
```

## 3. 검증 포인트

1. **초안 작성 품질**: 자유 서술 목표를 입력했을 때 3단 수락 기준 블록이 빈틈없이 규격대로 생성되는가?
2. **재시도 상한 준수**: 동일 작업자가 1차 실패 시 `RETRY_1`로 전이되고, 2차 실패 시 `REASSIGNED_1`로 전이되는가?
3. **재할당 상한 준수**: 총 2회 재할당 후에도 실패할 경우 `FAILED_PERMANENTLY`로 안전하게 종료되는가?
4. **브랜치 인계 체인**: `feat/task-user1` → `feat/task-user1-user2` 형태로 원본 커밋 이력이 보존되는가?
5. **단위 테스트**: `tests/test_host_bot.py`를 작성하여 상태 전이 및 초안 작성 모듈 100% 검증 통과.
